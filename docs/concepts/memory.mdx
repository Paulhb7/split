Split has **two memory layers**: the boss-facing **vault** and the
agent-private `var/memory/`.

## The vault (`$SPLIT_VAULT`)

A plain-markdown folder at `~/Documents/SplitVault` (override with the
`SPLIT_VAULT` env var) — the boss's data, deliberately outside `var/`, where
every expert files durable deliverables and durable facts. Layout:

- **`INDEX.md`** — the scope list, one line per project; inlined into every
  persona at session start (the boot-time recall trigger).
- **`_meta/boss-profile.md`** — durable facts about the boss, read first
  every session.
- **`notes/`** — the default bucket when no project is set.
- **`projects/<slug>/`** — deliverables + facts + a `MEMORY.md` index per
  project.

The doctrine (buckets, frontmatter vocabulary, index discipline, the
propose-a-project flow) is the `memory` skill
(`config/skills/memory/SKILL.md`), auto-mounted on every expert. The boss browses and edits the vault in-app via the **Vault overlay**
(🗃️ in the chrome bar) — tree on the left, TipTap editor on the right. The
filesystem is the single source of truth on both sides; agents write with
plain file operations, no API.

## Agent-private memory (`var/memory/`)

`var/memory/` is **cross-session memory**, separate from the workspace and
surviving a `rm -rf var/workspace/`:

- **`_user/USER.md`** — facts about the boss, shared by *every* expert.
- **`<expert>/MEMORY.md`** — each expert's own notes (Wolfgang's, Cicero's, …).

## How it's read

At session start, `core-rs/src/persona.rs::memory_text` reads these files and
`persona_text` prepends them to the persona. That lands in **both** channels:

- the projected `AGENTS.md` / `CLAUDE.md` / `.vibe/AGENTS.md`, and
- the runner's first-turn injection.

One helper, two channels — so harnesses that ignore workspace instruction files
still see the memory.

<Warning>
**Frozen-snapshot pattern:** writes during a session hit disk immediately but
only appear in the *next* session's snapshot.
</Warning>

## Writes are manual today

The agent writes when the boss says "remember X" or when it spots something
durable. Automatic post-turn extraction is future work for the planned
`split-memory` MCP server.
