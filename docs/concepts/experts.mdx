An expert is a *persona + skills + tools* that runs in its own session. The
**persona** is the identity and method, the **skills** are the kit it's allowed,
the **tools** are the MCP servers it can call. The bundle is portable — the same
expert runs unchanged on any harness.

<Note>
This page is the *mechanism*. For the roster itself — who's who, what each ships,
and how to drive them — see the **[Experts](/experts/overview)** tab.
</Note>

## Three categories

- **Super** — the jobs (Consultant, Scientist, Financier, Lawyer, Data Analyst,
  Engineer, Designer, Influencer). Productivity on tasks you already do.
- **Genius** — the unlocks (DaVinci, Curie, Tesla, Ride, Maradona, Brontë,
  Wolfgang, Homer, Hitchcock, Socrates…). Outputs you couldn't produce alone.
- **Coach** — the growth (Diet, Learning, Sport, Cooking). A domain to improve at.

See [Choosing an expert](/experts/choosing) for the full table.

## `kind` is a render hint

Each expert carries a `kind` (researcher / advisor / analyst / builder / finder /
operator / creator / coach…). It's **informational** — it tells the UI how to
render the session (a chat panel vs. a step feed vs. an app preview), nothing
more.

## Where they live

- **Personas:** `config/experts/<slug>.md` — the prompt projected at session start.
- **Registry:** `config/experts.json`, keyed by slug, each
  `{label, category, kind, skills, starters, blurb, status?}`. The slug is the
  stable id; `status: "next"` keeps an expert in the **Cabinet** (visible, not yet
  on the active picker). User-created experts live in
  `<VAR_DIR>/experts/<slug>.{md,json}`.

The persona is projected into the workspace's `AGENTS.md` (plus `CLAUDE.md` /
`GEMINI.md` / `QWEN.md` shims) so any harness running the expert sees the same
identity. See [The model](/get-started/the-model).
