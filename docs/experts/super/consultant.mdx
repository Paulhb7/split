<Info>**Super** · researcher · slug `consultant`</Info>

You bring a question — a market, a competitor, a decision to defend.
Consultant runs the full loop in one turn: pulls live sources, builds a
real deliverable, and hands you the file — packed slides or a board-ready
memo, every claim cited.

## What it delivers

A finished, source-backed deliverable in the same turn:

- a **dense HTML deck** (7-10 slides, default preset `split-default` — dark
  glass + coral): every non-cover slide carries 4-6 sourced data points —
  numbers, named companies, exact quotes, dates — with the publisher + date
  in the slide footer, not an appendix,
- or a **markdown memo** when the audience reads instead of watches (board
  pre-read, advisory letter): Kicker → Title → TL;DR → What we found → Why
  it matters → Recommendation → Risks → Sources,
- **Slide 1 is always "What I assumed"** (audience, scope, period, sources)
  and the **last slide is always Sources** — every URL actually used, with
  publisher and date.

Built for three request shapes: a single-slide **meeting brief**, a 7-10
slide **deep analysis**, a 5-8 slide **benchmark** (criteria × candidates
matrix with numeric scores, one slide per candidate, verdict by usage profile).

## When to pick it

Pick **Consultant** for market entry, competitive reviews, pricing
comparisons, meeting prep, or turning a document into a deck — anything that
needs live web research synthesized into a polished business deliverable.
Pick [Scientist](/experts/super/scientist) instead when the corpus is
academic literature (papers, field maps, idea bridges) rather than markets
and companies.

## How to drive it

State the question and the audience:

```
Assess our EU market entry
Compare 3 pricing strategies
Build a competitive review in slides
```

Attach a PDF, docx, or web page and say "make it a deck" — Consultant reads
it end to end, recreates the key charts/tables, and fills the gaps with
sourced facts rather than paraphrasing into generic bullets.

## What comes back

Slides render **live in the artifact pane**; a memo opens in Split's WYSIWYG
editor and stays editable in place. Both are saved to
`~/Desktop/<topic>-<YYYYMMDD>.<ext>` — Consultant reports the absolute path
and offers to `open` it. Iterating edits v1 in place and re-opens; a new
file is only created when you say "redo". Export to docx/PDF is a follow-up
on request.

## Leans on

Native web search plus one HTML build skill — see [Skills](/concepts/skills):

| Skill | Role |
|---|---|
| web search (native) | the harness's grounded search — wide, multi-angle queries; primary sources fetched and read, not just snippeted |
| `frontend-slides` | the packed HTML decks (preset `split-default`) — varied layouts (cover · statement · KPI · chart · 2×2 · table · sources) |

Markdown memos are produced directly (plain `.md`), no separate skill.

## Prerequisites & limits

- **Web search is the harness's native grounded search** — no Split-managed
  key. It runs on whichever coding agent you signed in to.
- **Cite or drop.** Every non-obvious claim gets a citation; an invented TAM
  is treated as a firing offence. If a number can't be verified, Consultant
  says so plainly or drops the claim, and separates fact from inference.
- **Slides over substance, never vibes.** Three vague bullets is a failed
  slide — the persona's bar is concrete numbers, named people, exact quotes.
  This makes a thin-source topic a short deck, not a padded one.
- **docx/PDF export is a follow-up**, not the default output.
