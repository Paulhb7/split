<Info>**Super** · creator · slug `designer`</Info>

You bring *"I want an app / site that…"*. Designer turns it into a gorgeous,
**interactive front-end mockup** you can see, click, and react to.

It designs the look and feel — it does **not** build the real thing. When the
mockup is right, it hands it to Engineer.

## What it delivers

A **single-file HTML mockup** — inline CSS/JS, CDN libs when they earn it — with
real layout, navigation, and hover/focus states, populated with fake data. A
mobile design is framed in a device bezel (status bar, notch); a desktop one in
browser/window chrome, so the fidelity reads as a real product, not a screenshot.

It designs **beyond the happy path** — the empty, loading, and error states too.
Every mockup opens with a small exec-summary banner: why it exists, the assumed
style, and how to read it (prototype, fake data). When the brief is wide it
exposes 2–3 directions in a bottom-right **"Tweaks"** panel to flip between.

## When to pick it

Pick **Designer** to settle the *look* first — to see and react to product UI
before anything is built. Pick [Engineer](/experts/super/engineer) instead when
you want the *working* app. When the mockup is right, Designer hands a short
build spec straight to [Engineer](/experts/super/engineer).

## How to drive it

Describe the screen, or point at one to redesign:

```
Mock up an app from this idea
Redesign this screen
Propose 3 visual directions
```

Attach real material — a UI kit, brand assets, a codebase to match, or
screenshots. Good design is never from scratch; mocking from nothing is the last
resort and yields generic look-alikes.

## What comes back

The mockup renders **live in the artifact pane** and is saved to
`~/Documents/split-apps/<slug>/index.html`. Iterations edit it in place — a new
file only on an explicit "redo from scratch". When it's right, you get a build
spec (screens + nav, key components, stack, what's fake) and the handoff line to
Engineer.

## Prerequisites & limits

- **Mockups, not working apps.** It produces interactive front-ends with fake
  data; it does not wire real backends, auth, or live data — that's
  [Engineer](/experts/super/engineer)'s job, via the handoff.
- **Runs locally:** no account or key needed to design and preview.
- **Material in, quality out:** with no brand or reference to work from it picks
  one aesthetic direction and owns it, but the result is stronger when you attach
  real assets.
